# ADR 0005 — 文字のフチ・影と schema 0.3.0-core

状態：採用／2026-10-10

## 背景

売り出し型のデザインでは、価格の白フチと影が欠かせない。Phase 0では同じ文字を8方向にずらして重ねて代用したが、量産すると価格の差し替えが10か所に増え、1か所でも漏れると古い数字のフチが残る。また、サイズ違いの版で文字サイズを変えても行送りを変えられず、枠を作れなかった。

## 決定

schemaを **0.3.0-core** に上げる。エンジンは0.2.0-coreと0.3.0-coreの両方を読む。以下は0.3でだけ許可し、0.2の文書に書かれていれば `E_SCHEMA` にする。

1. `text` ノードの `outline`：`{color, width}`。`width` は **字形の外側に見える太さ（du）**。内部では2×widthの線を、角を丸めて（round join）字形の後ろに描く。
2. `text` ノードの `shadow`：`{color, opacity, offsetX, offsetY, blur}`。フチがあれば、フチを含めた形の影になる。`blur` はdu単位の半径で、Skiaの換算 σ＝0.57735×blur＋0.5 を使う（0なら輪郭のはっきりした影）。
3. `nodePatch.lineHeight`：版ごとの行送り（text ノードだけ）。

### 描画方法

SkParagraphには組んだ後に塗りを差し替えるAPIが無い。そのため、同じ文字列・同じスタイル・同じ幅で、影→フチ→本体の順に最大3回組んで描く。影とフチの回は、改行位置・行幅が本体の回と **完全一致** することを毎回照合し、一致しなければ `E_RENDER_FAILED` で停止する。

fitや文字あふれの判定は本体の文字組みだけで行う。フチと影は枠の外へはみ出しうる。どこまで許すかは作者がデザインで決める。

## 検証

- 既存の0.2文書5件の出力hashは、変更前後で同一（既存の描画を変えていない）。
- テスト：フチ・影で白・紺の画素が増えること、影の有無で改行と採用サイズが変わらないこと、ぼかし付きの影も反復で一致すること、0.2の文書でフチを使うと拒否されること、値の範囲。

## 残る課題

- 要素同士の重なり（例：価格のカンマと注記）は検出しない。デザイン上の確認が必要。
- 文字単位の色・太さの切り替え（1つの枠の中で一部だけ赤くする等）は未実装。
