# 01 — 要件定義

版：0.2／2026-10-10。以下の「必須」は製品の要求仕様であり、実装済みを意味しない。

## 1. 製品の目的

SILIQ Creative Generatorは、独自のグラフィックエディターと、承認済みデザインの量産エンジンを統合したデスクトップアプリだ。

ユーザーはアプリ内でレイアウト、画像、ロゴ、書体、文字組み、色、図形、装飾を制作する。その後、差し替えてよい箇所と許容範囲を定義し、画像・文字データから大量の成果物を生成する。

品質は「AIらしい装飾」や「機能数」ではなく、意図した位置・字形・配色・画質を維持できること、同条件で再現できること、破綻を検出して止められることで評価する。

想定用途は、広告バナー、SNS静止画、商品告知、店舗別キャンペーン、サムネイル、イベント告知。特定の店舗業種やSILIQの色だけに固定しない。ブランド設定は案件ごとに分離する。

## 2. 変更してはいけない条件

| ID | 必須条件 | 検証の要点 |
|---|---|---|
| OFF-001 | インストール済みアプリは、初回起動から新規制作・編集・保存・復旧・量産・書き出しまでネット接続を必要としない | クリーンな実機でネットを遮断し一連の操作を完了 |
| OFF-002 | アプリ由来の外向き通信、DNS要求、外部への接続試行、アプリのTCP/UDP待受を設けない | オンライン環境でもプロセス単位の監視で検査 |
| AI-001 | 実行時にAI、LLM、MLモデル、推論ランタイム、AI SDKを使用しない | 配布物・依存・起動プロセス・処理経路を検査 |
| DES-001 | デザインの決定権はユーザーにある | 許可外の色・書体・ロゴ・位置の変更を拒否 |
| REP-001 | 固定した入力と実行環境で再現できる | 同一ビルド・同一リソース・同一設定の反復試験 |
| SEC-001 | 明示的に選択した素材・プロジェクト・出力先とアプリ専用領域だけにアクセスする | 範囲外ファイル、パストラバーサル、権限取消の否定試験 |

「オフラインで使えるが、接続時は解析情報を送る」という設計は不合格。ローカルLLMやローカルの人物認識・背景除去モデルもAI-001に反する。手動マスク、色閾値、幾何計算、通常の画像フィルターは対象外だが、その挙動を明示する。

開発時のClaude Code・依存取得・署名等は製品ランタイムと別の境界に置く。開発時までAI不使用／完全オフラインとする要求ではない。実際の顧客素材を開発支援へ送る許可はこの要件に含めない。

## 3. 成功条件

ひとつのデザインを作る→可変項目を設定する→保存する→別データで繰り返し制作する、という一連の操作がアプリだけで完結すること。

例：30件の店舗データと各店舗の画像を取り込み、承認済みの正方形・縦長・横長の3レイアウトへ展開する。90件の候補を検査し、問題のないものを指定フォーマットで生成する。30×3＝90という件数は使用例であり、速度を保証する実績ではない。

評価項目は、手修正件数、1件当たり操作時間、検査で止めた不良、再生成の一致、保存・復旧の成功。手動制作との時間削減率は比較測定してから記載する。

## 4. 利用形態と権限

v1は単一ユーザー・単一端末。ログイン、組織管理、共同編集、クラウドライブラリは持たない。「制作モード」と「量産モード」は操作モードであり、ユーザー認証によるセキュリティ権限ではない。

制作モードでは文書を編集できる。承認済みテンプレートに変更を加える場合は新しい版を作り、旧版を維持する。量産モードでは公開済みスロットだけを入力できる。ロックされたレイヤーの移動、色変更、ロゴ変更、変数による任意プロパティの書き換えは禁止する。

v1の最初の実機対象はmacOS／Apple Siliconと仮置きする。Intel Mac／Windowsへの対応を当然に成立したものとせず、依存ビルド、色、フォント、保存、配布、セキュリティの追加試験後に対応を宣言する。

## 5. 画面・操作の設計

主要な作業領域は5つに絞る。

| 領域 | 内容 |
|---|---|
| 中央キャンバス | アートボード、実描画、ガイド、選択枠、比較表示 |
| 左ペイン | アートボード、レイヤーツリー、グループ、ロック、表示状態 |
| 右ペイン | 座標・寸法、画像、文字組み、塗り、線、効果、スロット設定 |
| 素材・ブランドパネル | 取り込んだ画像、ロゴ、使用可能フォント、スウォッチ、スタイル |
| 量産・検査パネル | データ列対応、全件サムネイル、エラー、出力プリセット、ジョブ進捗 |

新規作成、開く、保存、別名保存、取り込み、Undo/Redo、整列、ズーム、書き出しはキーボード操作を持つ。OSの標準的なショートカットに合わせ、入力欄・日本語IMEと衝突させない。見た目だけの未実装ボタンは置かない。

プロパティは数値で正確に入力できること。ドラッグは補助であり、微細な位置決めの唯一の手段にしない。画面装飾は抑え、作品の色と競合しないニュートラルなUIとする。

## 6. 文書・エディター機能

| ID | v1必須要件 |
|---|---|
| DOC-001 | 複数アートボード、任意ピクセル寸法、ルーラー、ガイド、セーフエリア、グリッド |
| DOC-002 | 画像・テキスト・図形・ベジェパス・グループ・ロゴの安定IDを持つレイヤー構造 |
| EDT-001 | 選択、複数選択、移動、拡大縮小、回転、複製、順序、整列、均等配置、スナップ |
| EDT-002 | ベジェパスの作成、アンカー・ハンドル編集、閉じたパス、複合パス、塗り規則 |
| EDT-003 | 非破壊のクリップ、線形／放射グラデーション、透明度、線、限定した描画モード、影・ぼかし |
| EDT-004 | ひとまとまりの操作ごとのUndo/Redo。ドラッグ1回を数百回のUndoにしない |
| DOC-003 | バージョン付き独自形式の保存・再読込・自動復旧。将来版の文書は安全に拒否 |
| BRD-001 | 色・文字スタイル・ロゴを名前付きで管理。テンプレートに版を固定して取り込む |

描画モードは最初にnormal・multiply・screenなど検証対象を明示して実装し、未対応のモードを見かけだけ選択可能にしない。効果の順番は文書に保存し、UI表示順と実描画順を一致させる。

画像は元データを維持し、crop・fit・focal point・変形・マスク・色調整をパラメーターとして保存する。初期画像調整は明示的な明るさ／コントラスト／彩度などの決定論的処理に限定する。

## 7. 文字組み要件

対象は日本語・英語の横組み。ポイント文字と領域文字、段落揃え、複数スタイルの文字列、サイズ、字間、行間、ベースライン補正、明示的なOpenType設定を扱う。フォントファミリー名だけでなく実ファイルのハッシュ、face index、採用した機能設定を固定する。

| ID | 必須要件 |
|---|---|
| TXT-001 | 日本語IMEの変換中と確定後を区別し、文字の二重挿入やUndo破損を起こさない |
| TXT-002 | 指定フォント、glyph coverage、字形配置、行幅、改行位置を実エンジンで検査する |
| TXT-003 | 最低サイズ、最大行数、手動改行、禁則、最大テキスト領域をテンプレートに保存 |
| TXT-004 | 不足フォント・不足グリフ・解消不能な文字あふれは出力停止。無断置換や省略をしない |
| TXT-005 | 文字のfitはユーザーが許可したサイズ候補等の有限集合だけを探索し、適用値を記録 |

既定のあふれ方針はerror。縮小を許可したときだけ、例えば64→63→…→56の順で実際に組み、最初に収まった値を選ぶ。56でも収まらなければ停止する。横長に潰す、字間を勝手に詰める、語尾を削る、フォントを変えることはしない。

人名・店舗名・価格などのテキストは原文を維持する。Unicode正規化や数値変換を暗黙に行わない。必要な整形は明示的な入力規則としてプレビューで確認する。

禁則はW3C日本語組版資料とUnicodeの分割規則を参照し、v1で対応する範囲を試験表にする。HarfBuzzだけでは段落折り返し等まで完成しないため、文字形成と段落・禁則・fitを分ける。[S04][S05]

縦組み、ルビ、圏点、割注、複雑な段組み、パス上文字、カラーフォント、可変フォントの全軸は後続ゲート。未検証なのに「日本語完全対応」と表示しない。

## 8. 素材・フォント・ロゴ

| ID | 要件 |
|---|---|
| AST-001 | PNG・JPEG・静止WebPを内容に基づいて識別し、安全なデコーダーで取り込む |
| AST-002 | SVGロゴは許可サブセットだけを独自ノードへ変換。未対応内容を黙って消さない |
| AST-003 | EXIFの向きを一度だけ適用し、色プロファイル変換の結果を記録する |
| AST-004 | cover／contain、焦点位置、保護領域、回転、クリップを保存する |
| FNT-001 | ローカルのTTF／OTFと検証済みTTC faceを登録。自動取得しない |
| FNT-002 | フォント同梱・埋め込み・持ち出しの可否を区別。許可未確認の自動同梱はしない |
| LOG-001 | ロゴは許可されたasset IDだけを選択でき、比率保持、最低幅、クリアスペースを検査 |

ロゴのクリアスペースや保護領域はユーザーが設定する。AIや画像認識でロゴの意味を推測しない。写真の主役位置も、既定の中心かユーザーが指定した焦点を使う。

PDF・AI・PSD・INDDの編集可能な取り込み、HEIC、アニメーション画像、Web取得はv1の対象外。SVGのfilter／foreignObject／script／外部参照等は許可しないか、別途承認した安全な変換経路で扱う。v1は未対応エラーを基本とする。

## 9. テンプレートと多サイズ展開

| ID | 要件 |
|---|---|
| TPL-001 | 変数スロットの種類、必須／任意、入力上限、対応ノード、変更可能な属性を宣言 |
| TPL-002 | レイアウト・ブランド・素材の版を固定した承認済みテンプレートを保存 |
| VAR-001 | サイズごとのアートボードまたは明示的overrideを作者が設計し、承認して登録 |
| VAR-002 | 指定されていない縦横比は勝手に再構成せず「レイアウト未定義」とする |
| TPL-003 | 制約違反は該当ノードと修正方法を表示。固定部分を変えて解決しない |

多サイズは画像の一律縮小ではない。正方形では左右、縦長では上下など、ユーザーが別々に設計したレイアウトを、同じスロットのデータへ適用する。

v1の制約は、親基準のアンカー、固定値、比率、最小／最大寸法、定義済みのノード参照に絞る。循環参照や過剰な制約は事前検査で拒否する。任意スクリプトを評価する汎用レイアウト言語は作らない。

## 10. バッチと出力

| ID | 要件 |
|---|---|
| BAT-001 | CSV／JSONを読み込み、列→スロットをGUIで対応付ける。画像は承認したフォルダー等からasset IDへ登録 |
| BAT-002 | 行×variant×出力形式を全件検査し、全体件数・正常・警告・エラーを表示 |
| BAT-003 | ジョブ開始時の文書・データ・素材・フォント・エンジン設定を固定する |
| BAT-004 | 進捗、停止、キャンセル、障害後の再開、失敗分のみ再実行を扱う |
| BAT-005 | 出力名を事前確認し、重複・危険なパス・意図しない上書きを拒否する |
| EXP-001 | PNG、JPEG、WebPをsRGBで出力。寸法、alpha、JPEG背景色、品質設定を明示する |
| EXP-002 | SVGは互換サブセットで書き出し、ネイティブ文書の完全保存形式とは区別する |
| EXP-003 | PDFはRGB校正用途として提供。ラスタライズ箇所と文字の編集性を明示する |
| PRE-001 | 文字・素材・ロゴ・サイズ・効果・色・出力先・出力形式のプリフライトを提供 |

標準のバッチは、ERRORが1件でもあれば開始前に停止する。「正常な行だけ出力」はユーザーが明示的に選んだ場合に限り許可し、結果をcompleted_with_errorsとして区別する。大量の出力があっても、欠落を成功として隠さない。

CSVはUTF-8を既定とし、別エンコーディングは明示的な選択とプレビューを必要とする。IDの先頭ゼロを落とさない。数式は評価しない。CSVをレポートとして出力するときは表計算ソフトでの式解釈に備える。

PNGは透過可。JPEGは透過不可のため、背景色を未指定のまま合成色を決めない。WebPのlossless／lossyを明示する。画像の自動アップスケールを高画質化と称しない。

SVG・PDFで正確に表現できない効果は、未対応エラーとするか、ユーザーが許可した範囲でラスタライズし、対象・解像度を記録する。SkiaのPDFバックエンドにも未対応や変換される機能があるため、出力できたという事実だけで再現性を保証しない。[S06]

## 11. 品質保証の範囲

v1はデジタル静止画の高品質な制作・量産、およびRGB校正PDFを対象とする。sRGBを作業・出力基準とし、ICC情報のある画像は規定経路で変換する。未タグ画像の扱いは「sRGBと仮定」を明示し、必要なら入力拒否に設定できる。[S07]

CMYK、特色、オーバープリント、PDF/X、印刷会社固有のICC、実機RIPでの確認は商業印刷リリースの別要件とする。塗り足しらしい領域を付けただけで「入稿対応」と呼ばない。

## 12. 非目標

Illustrator全機能の再実装、Adobe固有形式との完全往復、クラウド共有、共同編集、オンライン素材検索、AIによるレイアウト提案・評価・画像生成、ユーザー作成コード／プラグインの実行、動画・3D・アニメーションはv1で行わない。

これらの非目標と、ベジェ編集・文字組み・マスク等を持つ独自エディターであることは両立する。汎用ツールの全機能ではなく、承認済みデザインの正確な編集と量産に集中する。
